# 🗄️ KarigarConnect Database Operations & Migrations Guide

This guide documents the database architecture, schema migrations, backup, restore, and operational procedures for the **KarigarConnect Artisan App** PostgreSQL database.

---

### Table Summary & Foreign Key Rules

| Table | Primary Key | Foreign Keys & Cascade Behavior | Key Constraints & Indexes |
| :--- | :--- | :--- | :--- |
| `users` | `id` | None | `firebase_uid` (UNIQUE, Indexed) |
| `products` | `id` | `user_id → users.id` (`CASCADE`) | Costs $\ge 0$, Valid Statuses, Indexed on `user_id`, `category`, `status` |
| `product_images` | `id` | `product_id → products.id` (`CASCADE`) | Indexed on `product_id` |
| `product_audio` | `id` | `product_id → products.id` (`CASCADE`) | Indexed on `product_id` |
| `prices` | `id` | `product_id → products.id` (`CASCADE`) | Prices $\ge 0$, `maximum >= minimum`, Indexed on `product_id` |
| `catalogs` | `id` | `user_id → users.id` (`CASCADE`) | Status in `('draft', 'published', 'archived')`, Indexed on `user_id`, `status` |
| `catalog_products` | `(catalog_id, product_id)` | `catalog_id → catalogs.id` (`CASCADE`), `product_id → products.id` (`CASCADE`) | `UNIQUE(catalog_id, product_id)` |
| `buyers` | `id` | None | Indexed on `company`, `location`, `category` |
| `enquiries` | `id` | `buyer_id → buyers.id` (`CASCADE`), `product_id → products.id` (`CASCADE`) | Status in `('pending', 'contacted', 'accepted', 'rejected')` |
| `notifications` | `id` | `user_id → users.id` (`CASCADE`), `product_id` (`SET NULL`), `enquiry_id` (`SET NULL`) | Default `is_read=false`, Indexed on `user_id`, `is_read`, `created_at` |

## 🚀 Migration Operations with Alembic

Alembic tracks versioned database schema transformations in `backend/alembic/versions/`.

### 1. Apply All Pending Migrations (Deploy / Startup)
```bash
# Activate virtual environment
source venv/bin/activate

# Upgrade database to the latest revision
alembic upgrade head
```

### 2. Check Current Migration Status
```bash
alembic current
alembic history --verbose
```

### 3. Generate a New Migration Revision
> [!IMPORTANT]
> Always review autogenerated migration scripts before applying them to staging or production.

```bash
alembic revision --autogenerate -m "add_field_name_to_table"
```

### 4. Rollback / Downgrade Migrations
```bash
# Rollback one revision
alembic downgrade -1

# Rollback to base (empty database)
alembic downgrade base
```

## 💾 Database Backup & Recovery (PostgreSQL)

> [!CAUTION]
> Production backups should be scheduled regularly and stored securely offsite (e.g. encrypted S3 bucket). Never commit `.dump` or `.sql` files with real user data to Git.

### 1. Create a Full Logical Backup (`pg_dump`)
```bash
# Compressed custom-format backup (Recommended)
pg_dump -Fc --no-acl --no-owner -h localhost -U postgres -d artisan_db > backup_$(date +%Y%m%d_%H%M%S).dump

# Plain SQL backup
pg_dump --no-acl --no-owner -h localhost -U postgres -d artisan_db > backup_$(date +%Y%m%d_%H%M%S).sql
```

### 2. Restore Database from Backup (`pg_restore` / `psql`)
```bash
# Restore from custom-format backup (.dump)
pg_restore --clean --if-exists --no-acl --no-owner -h localhost -U postgres -d artisan_db backup_20260908_120000.dump

# Restore from plain SQL backup (.sql)
psql -h localhost -U postgres -d artisan_db < backup_20260908_120000.sql
```

## ⚙️ Environment Configuration

Set the database connection URLs in `backend/.env`:

```env
# Local / Staging / Production Database
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/artisan_db

# Optional Test Database (defaults to SQLite in-memory or test database)
TEST_DATABASE_URL=sqlite:///:memory:
```

### Hosted Provider URL Normalization
Hosted cloud databases (Render, Railway, Supabase) often supply connection strings starting with `postgres://`.
The backend automatically normalizes `postgres://` to `postgresql://` in `app/database.py` and `alembic/env.py`.
