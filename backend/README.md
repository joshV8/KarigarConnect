# Artisan App — FastAPI Production Backend

Production-ready FastAPI backend for KarigarConnect / Artisan App:
**Flutter App ➔ HTTPS ➔ FastAPI ➔ PostgreSQL ➔ AI Service ➔ Cloudinary & Firebase**

---

## 1. Architecture & Capabilities

| Layer | Technology | Production Support |
|-------|------------|-------------------|
| **API Framework** | FastAPI (Python 3.12+) | Uvicorn ASGI with dynamic `$PORT` |
| **Database** | PostgreSQL (SQLAlchemy 2.0) | Hosted DB pool recycling, pre-ping & SSL |
| **Authentication** | Firebase Admin SDK | ID Token verification + local mock mode |
| **Asset Storage** | Cloudinary | Product photos + voice recordings (`.m4a`/`.wav`) |
| **AI Multimodal** | Person 2 Service / Mock | Voice STT, Translation, Auto-description & SEO |
| **Pricing Engine** | Cost + Labour + Margin | Dynamic margin & market adjustments |
| **Market Linkage** | B2B Buyer Matching | Category matching & wholesale enquiries |

## 3. Local Development Setup

```bash
# 1. Navigate to backend directory
cd backend

# 2. Setup virtual environment
python3 -m venv venv
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Copy environment template
cp .env.example .env

# 5. Start development server
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

Interactive API Documentation:
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Versioned Swagger: `http://localhost:8000/api/v1/docs`

## 4. PostgreSQL Configuration

### Local Database:
```sql
CREATE DATABASE artisan_db;
```
Set in `.env`:
```text
DATABASE_URL=postgresql://postgres:password@localhost:5432/artisan_db
```

### Hosted Database (Render, Railway, Supabase, Neon):
Provide the database connection string directly:
```text
DATABASE_URL=postgres://artisan_user:secret@dpg-xxxx.oregon-postgres.render.com/artisan_db
```
*(The backend automatically normalizes `postgres://` to `postgresql://` and enables connection pool pre-ping and recycling).*

### 4.1 Database Migrations (Alembic) & Seeding

The database uses Alembic to manage versioned migrations:

```bash
# Apply all pending migrations to latest schema
alembic upgrade head

# Rollback latest migration
alembic downgrade -1

# Generate a new migration revision (always review autogenerated scripts!)
alembic revision --autogenerate -m "description"

# Seed database with verified fictional B2B buyers (idempotent)
python -m app.seed
```
For complete backup, restore, and operational procedures, see [DATABASE_OPERATIONS.md](DATABASE_OPERATIONS.md).

## 5. Cloudinary & Firebase Setup

### Cloudinary (Media Assets):
Set credentials in environment variables:
```text
CLOUDINARY_CLOUD_NAME=my_cloud
CLOUDINARY_API_KEY=123456789
CLOUDINARY_API_SECRET=my_secret
```
*When unconfigured in local development, uploads fall back to the `/uploads` directory.*

### Firebase Authentication:
In production (`AUTH_MODE=firebase`), provide the service account credentials:
```text
AUTH_MODE=firebase
FIREBASE_PROJECT_ID=artisan-connect-sih
FIREBASE_CLIENT_EMAIL=firebase-adminsdk@artisan-connect-sih.iam.gserviceaccount.com
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
```
In development (`AUTH_MODE=mock`), pass any mock token (`Authorization: Bearer artisan_1`) to auto-provision test artisans.

## 6. Deployment Guide

### Option A: Deploy to Render (Recommended)

1. Connect your repository to **Render** (render.com).
2. Click **New +** ➔ **Blueprint** and select `backend/render.yaml` (or create a Web Service manually).
3. **Build Command**: `pip install -r requirements.txt`
4. **Start Command**: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. **Health Check Path**: `/health`
6. Set the Environment Variables in the Render dashboard.

### Option B: Deploy to Railway

1. Install Railway CLI or connect via GitHub: `railway up`
2. Railway will automatically detect the `backend/Dockerfile` or `backend/Procfile`.
3. Set environment variables in the Railway dashboard.

### Option C: Docker Deployment

```bash
# Build the production image
docker build -t artisan-backend .

# Run the container
docker run -p 8000:8000 \
  -e ENVIRONMENT=production \
  -e DATABASE_URL="postgresql://..." \
  artisan-backend
```

## 8. Automated Test Suite & CI

The backend includes a comprehensive, isolated test suite covering all domains (Health, Auth, Products, Pricing, Catalogs, Buyers, Enquiries, Uploads, AI Processing, and End-to-End flows).

### Running Tests:
```bash
cd backend

# Run the complete test suite
pytest

# Run with verbose output
pytest -v

# Run specific test file
pytest tests/test_products.py -v
```

### Test Database Configuration:
By default, tests run against an isolated in-memory SQLite database (`TEST_DATABASE_URL="sqlite:///:memory:"`) without modifying production data.

To test against a PostgreSQL test database:
```bash
TEST_DATABASE_URL="postgresql://test_user:test_password@localhost:5432/test_artisan_db" pytest -v
```

### Continuous Integration:
A GitHub Actions workflow is located at `.github/workflows/backend-tests.yml` to automatically execute the test suite with a live PostgreSQL container on every push and pull request.
